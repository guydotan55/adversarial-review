# Contributing

Issues and pull requests are welcome.

- This is a prompt, so wording is behavior. Changing one rule can silently weaken another.
- Before opening a PR that edits `SKILL.md` or `references/`, run the scenarios in `evals/README.md` and add a dated entry to `evals/RESULTS.md`.
- Say which model ran each seat, and compare full catches first, partial catches second.
- Never put real names, paths, tokens or private project details in the repo, including in eval fixtures.
- Keep the rules in `SKILL.md` consistent with the verdict and severity definitions; if a change weakens independence or the consent gate, say so in the PR.
